# MVP Agent 执行过程交互规范

版本：v0.1 · 日期：2026-09-11。

本文细化 PRD F03–F05，不增加长期 Memory、任务规划系统或新业务模块。

## 1. 页面呈现

一次用户请求对应一个执行过程。主对话区固定按“用户请求 → 执行过程 → 最终回答 → 产物”排列。交互节奏参考 Codex：运行中持续更新工作动态，结束后将过程折叠成一行摘要，正式回答从摘要下方开始。

以下仅为布局示意，实际步骤、文字与耗时来自真实执行：

```text
你：帮我修复这个函数，并运行测试。

● 正在工作 · 8 秒                         [停止]
│ ✓ 搜索文件   src/                       3 个匹配
│ ✓ 读取文件   src/example.ts
│ ✓ 修改文件   src/example.ts             +4 −2
│ ◌ 执行命令   npm test                   运行中

任务结束后：
▸ 已工作 12 秒 · 4 个步骤

已修复空数组输入导致的越界问题，并通过现有测试。
```

运行时过程面板默认展开，新增步骤在面板内部出现。正常结束后自动折叠；若用户正在展开工具详情、选择过程文本或已向上滚动，则保持展开并提供手动折叠入口。失败或停止的过程默认展开，方便用户理解原因。

最终回答在任务结束前不放空白占位。结束时先稳定过程摘要，再插入回答，减少页面跳动。重新打开历史会话时，已完成过程默认折叠。

## 2. 思考展示

思考以独立行呈现（图标 + 文案），不显示成段文本日志：

| 情况 | 展示 |
| --- | --- |
| 已发出请求，尚无内容 | 一行"思考"，图标缓慢旋转 |
| 思考流式输出中 | 一行"思考"，后跟最近思考内容的单行脉冲闪动（不展示成段文本） |
| 思考结束 | 一行"思考 · 持续了 x 秒"，可点击展开/收起完整思考内容（缩进引用块） |
| 模型未提供思考内容 | 不显示空的思考行，直接展示正文与工具 |
| 历史会话加载 | 思考行显示为"思考"（无耗时数据时），同样可展开 |

只渲染厂商实际返回、引擎允许应用读取的展示内容；不得用前端生成的"分析中→制定计划→检查结果"文案伪装真实思考。思考内容不是系统执行日志，也不是长期 Memory。

## 3. 工具卡片

每次实际调用有独立 toolCallId，卡片用同一个 ID 从运行态更新到终态；同名工具多次调用不能合并成一条。工具参数尚未完整时只显示“准备调用”，不呈现半截 JSON 为最终参数。

摘要层包含图标、动作名称、主要目标、状态；运行中显示耗时，结束后保留实际耗时。状态至少区分运行中、成功、失败、已取消和中断/结果未知，不能只靠颜色。

| 工具类型 | 默认摘要 | 展开详情 |
| --- | --- | --- |
| 文件搜索/内容搜索 | 搜索范围、关键词、匹配数（实际可得时） | 查询参数与返回结果 |
| 文件读取 | 相对路径、读取范围（实际可得时） | 本次读取的文本结果 |
| 文件写入/修改 | 路径、新建/修改、增删统计（可计算时） | 本次修改的 before/after diff |
| Shell | 命令短标题、运行/退出状态 | 完整命令、cwd、stdout/stderr、退出码 |
| 未知扩展工具 | 工具名与结果摘要 | 格式化参数与结果，使用通用组件 |

- 相对路径便于阅读，悬停显示完整路径；内容过长时允许横向滚动或换行，不撑破页面。
- 命令完整文本可在执行时查看，但卡片不提供“一键重跑工具”；重试通过下一条用户消息重新交由 Agent 处理。
- 工具没有输出时显示“执行中，暂无输出”，不模拟终端日志。
- 大输出折叠、截断并提供“查看完整输出”；截断是界面行为，必须标识。
- diff 来自本次修改捕获的实际前后内容；没有可信快照时显示摘要，不能拿后来文件内容冒充本次结果。
- diff 标识“已修改”，MVP 不增加 Apply 按钮、审批式编辑或自动回滚。
- 输出中的链接、Markdown 和代码均作数据展示，不作为页面脚本执行。

## 4. 过程分组与完成反馈

按一次用户请求分组，每个分组可显示工具调用次数和成功/失败数量；统计来源是工具事件，不是模型文本。默认不显示百分比进度或固定步骤清单，因为 Agent 的总步骤事先未知。

Agent 可以用普通文本解释计划，但 MVP 不把这类文字自动变成有完成勾选的任务规划器。

完成时：运行指示停止，输入框恢复发送；过程面板以 160–220 ms 收拢为摘要，最终回复显示在其下方。模型正常结束只能说明本轮执行结束，不自动生成“任务已验证成功”徽章。测试是否通过，以命令结果和实际验证信息为准。

某一步失败但 Agent 随后恢复时，原失败卡片保留；最终 run 可以正常结束。不能为了美观把全部历史图标改成绿色。

## 5. 停止与异常

点击停止后按钮立即反馈“正在停止”，不立刻伪造取消成功。收到 Runtime 终态后变为“已停止”。如果进程未退出，保留真实状态与恢复入口。

已完成工具维持原状态；正在运行但无法确认结果的工具标记“中断，结果未知”，不标为成功。已修改文件不会因停止自动恢复。

网络或鉴权错误展示在当前过程末尾，提供“修改模型配置”；Runtime 崩溃提供“重新启动 Runtime”。恢复进程只恢复可用状态，不自动重放命令。

运行期间浏览其他会话时，左栏运行标记和返回入口持续可见。一个活跃 run 的限制在服务端执行，不能仅靠禁用按钮。

## 6. 记忆与上下文的交互边界

| 概念 | MVP 行为 | 不应出现的误导 |
| --- | --- | --- |
| 会话历史 | 自动保存；重新打开可继续当前会话 | 不称为“跨会话长期记忆” |
| 上下文整理 | pi 实际压缩时显示“正在整理上下文”，结束后保留简短记录 | 不写“已永久记住你的偏好” |
| Token/上下文用量 | 有可靠数据时在模型附近显示，用 tooltip 解释 | 没有容量或用量数据时不显示虚假百分比 |
| Skills/上下文文件 | 可以显示实际已加载资源；按需读取有可观测事件时才显示读取记录 | 不宣称每一条内容都被模型采用 |
| 长期 Memory | 本轮不提供记住/遗忘按钮、自动积累动画或记忆面板 | 不用装饰卡片暗示能力已实现 |

后续若加入长期记忆，需要独立设计内容、来源、编辑、删除和跨会话召回；不与本轮思考折叠块混用。

## 7. 动效与滚动

- 正在执行的图标使用轻微旋转或呼吸；结束后以约 160 ms 过渡为静态状态图标。
- 思考/工具折叠采用 160–220 ms 高度或淡入过渡；长输出不做大段逐字动画。
- 当前状态更换只做轻微淡入淡出，不闪烁、不反复改变行高。
- 用户在底部才跟随新内容；手动向上滚动后显示“回到最新”。展开历史工具不把用户拉回底部。
- 切换主题或会话不重新播放历史步骤的执行动画。
- reduced motion 关闭循环和位移动画，保留清楚的文字状态与焦点。

## 8. 补充验收

1. 无思考输出的模型不出现空思考块；有思考/摘要输出时分类正确、可展开。
2. 连续执行多个同名工具，每次调用有独立记录，参数与结果不串卡片。
3. 工具失败后 Agent 成功恢复，原失败记录仍然可见。
4. 停止/崩溃后不再播放运行动画，不将未知工具结果标为成功。
5. 读取、修改、命令三类卡片均能查看详情；diff 明确是已执行结果。
6. 上下文压缩反馈由真实事件触发；任何页面都不暗示已实现长期 Memory。
7. 长输出、展开历史、手动上滚、主题切换均不造成跳动或焦点丢失。
8. 正常完成后过程默认折叠、回答位于下方；用户主动查看过程时不被强制折叠；失败和停止默认展开。

其中可控事件顺序用集成 fixture 验证；真实模型验收仍依照 MVP 三厂商要求，不因 fixture 通过而宣称厂商已验证。
