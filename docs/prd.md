# Office Agent MVP 产品需求文档

版本：v0.1  
日期：2026-09-11  
状态：需求基线，待实施验证  
范围依据：以用户最新确认的“好看的 UI + pi 基础能力”为准。  
当前阶段：**第二阶段（Agent 商业化体验）已确认**，见 [commercial-ui-prd.md](./commercial-ui-prd.md)，P0 六项实施中。

## 1. 产品定位

做一个基于 pi-coding-agent 的桌面个人 Agent。第一版聚焦顺手、精致的对话与编程体验：用户配置自己的模型，选择本地目录，通过自然语言让 Agent 读写文件、搜索内容、执行命令，并随时查看进度、停止执行、恢复会话。

项目首先服务于学习 Agent 和日常自用，同时为未来 Office 场景留下清楚的模块边界。复用 pi 的核心 Runtime，不重新实现 Agent Loop。

MVP 的产品承诺：**安装应用 → 配置模型 → 选择目录 → 完成一项真实本地任务 → 退出后继续会话。整个过程有一致、美观且可信的界面反馈。**

## 2. 用户与使用场景

核心用户是愿意配置 API Key、有本地文件或编程需求的个人用户。界面默认简体中文，字段结构为后续国际化留余地；MVP 不交付多语言切换。

主要场景：

1. 选择一个代码目录，让 Agent 解释结构、定位函数或分析错误。
2. 让 Agent 修改代码、创建文件、执行项目已有的测试命令。
3. 使用 DeepSeek、GLM 或自定义兼容接口完成同一类任务。
4. 观察每一步工具执行，出现错误时查看输出、修改要求并继续。
5. 关闭应用后重新打开，找到历史会话继续工作。

本轮不是完整 IDE，也不要求用户先建立 Office 数据、账号体系或知识库。

## 3. 目标与成功标准

| 目标 | 成功标准 |
| --- | --- |
| 真实 Agent 能力 | 至少一次完整完成文件搜索、读取、修改和命令执行的多步任务 |
| 模型配置可用 | DeepSeek、智谱 GLM、一个自定义 OpenAI Chat Completions 兼容服务分别通过真实文本、流式与工具调用验证 |
| 会话可靠 | 正常退出后历史可恢复；异常中断不会被展示为成功完成 |
| 视觉完成度 | 首次使用、空会话、长会话、工具运行、设置、错误和浅深主题均完成视觉检查 |
| 桌面交付 | Windows 11 x64 标准用户环境可安装、启动，无需预装系统 Node.js |
| 可演进 | 新增一个内置工具不需要修改 Agent Loop 或聊天页面主逻辑 |

“好看”与基础 Agent 能力同为 P0，不以漂亮静态页面替代真实功能，也不以功能跑通替代界面打磨。

## 4. 信息架构

MVP 只有三个主要界面：欢迎/新会话、会话详情、设置。欢迎页可以与空会话共用主区域。

```text
应用窗口
├─ 左侧栏：品牌、新建会话、会话搜索、历史列表、设置
├─ 主区域
│  ├─ 空会话：简洁欢迎语、目录选择、任务示例、输入框
│  └─ 会话：标题/目录/模型、消息与工具时间线、输入框
└─ 按需展开的详情区：工具参数、执行输出、文件修改 diff

设置
├─ 模型与厂商
├─ 外观与交互
└─ 运行环境与关于
```

不展示无法使用的 Knowledge、Todo、Calendar、KPI 导航和模拟进度卡片。未来可以扩展主导航，但首版保持聚焦。

## 5. 功能需求

### F01 首次启动与工作目录（P0）

- 首次启动引导配置模型；未配置时发送按钮给出明确的配置入口。
- 用户可以选择目录，也可以使用应用创建的默认工作目录。
- 主界面持续显示当前目录，路径过长时缩略，悬停可查看完整路径。
- 首次进入目录时解释 Agent 可以在当前用户权限下读写文件、执行命令，并记录该目录的信任选择。
- 当前目录并不构成操作系统沙箱；文案不得暗示 Agent 无法访问目录外资源。
- 活跃会话固定绑定目录；切换目录创建新会话，不把已有对话悄悄绑定到另一项目。
- 默认目录及应用数据位于用户可写位置，不能放在安装目录中。

验收：路径含中文和空格时可正常读取与执行；目录被移动或删除后提供重新定位或新建会话入口。

### F02 会话管理（P0）

- 新建会话、历史列表、打开历史、重命名、按标题搜索、删除。
- 初始标题由第一条用户消息截取，不额外消耗一次模型调用。
- 历史按最近活动排序；运行会话显示状态标记。
- 自动保存消息和工具历史，重启后可以继续。
- 删除需确认；运行中的会话先停止再删除。
- 同一时刻只允许一个 Agent run；运行时可以浏览其他历史会话，但不能启动第二个 run。
- 浏览历史时有明显入口回到运行中的会话。
- 会话分支、树导航和跨会话并发不在 MVP UI 范围。

验收：创建两个会话，重命名、搜索、切换、重启恢复、删除均可正常完成。

### F03 对话与输入（P0）

- 文本流式输出，支持 Markdown、代码高亮、代码复制和消息复制。
- 输入框自动增高；Enter 发送，Shift+Enter 换行；中文输入法组词回车不触发发送。
- 支持选择本地文件作为上下文引用，显示可移除的路径标签；工具按需读取，不无条件把整个文件塞进上下文。
- 运行期间用户可以编辑下一条草稿；MVP 不提供消息队列或 steering，发送在当前 run 结束后恢复。
- 发送按钮运行时切换为停止按钮；显示“正在停止”直到 Runtime 确认。
- 用户向上浏览时停止自动滚动，并提供“回到最新”；停留底部时自动跟随。
- 空状态提供 3 个真实任务示例，如“解释当前目录结构”“定位并修复一个错误”“创建一个脚本”。点击只填入草稿，不自动执行。
- 只展示模型实际返回且 pi 暴露的思考摘要/思考内容，不生成虚假的思考动画文案。
- 大段工具输出默认折叠，支持展开、复制和查看保存的完整输出。

验收：中英文、长代码块、长输出、模型失败、停止过程中界面保持可操作，无重复消息或跳动覆盖。

### F04 Agent 与编程工具（P0）

- 使用 pi 完成模型调用、工具循环、上下文管理和会话持久化。
- 支持读取、写入、精确编辑文件；支持目录枚举、路径搜索和内容搜索。
- 搜索优先复用所选 pi 版本已有工具；不足处用薄工具扩展补齐，不重写执行框架。
- 支持 Shell 命令执行，展示命令、工作目录、输出、退出状态和错误。
- 支持运行用户项目已有的测试、构建与脚本，前提是相关语言环境与依赖已存在。
- Windows 默认使用经验证的 PowerShell 工具适配；Ubuntu 使用 Bash。Git Bash 可作为后续/高级配置，不作为基础使用的安装前提。
- 文件修改展示文本 diff；明确这是已执行修改的结果，不是“待应用”预览。大型或二进制文件提供路径与摘要。
- 停止操作阻止后续模型/工具步骤，并尽力终止当前受控子进程树；已经写入的文件不会自动回滚。
- 自动上下文压缩复用 pi，在 UI 中显示真实压缩状态；不在前端自行总结历史。

验收：在准备好的示例工程中，Agent 搜索函数、读取代码、修改目标内容并运行验证命令，工具卡片与实际文件结果一致。

### F05 执行过程与异常（P0）

工具卡片、思考折叠块、上下文整理、状态动效和完整执行流程详见 [Agent 执行过程交互规范](./agent-interaction.md)，作为本节验收细则。

交互参考 Codex 的任务节奏：用户请求之后先显示持续更新的执行过程；任务结束后将过程收成一行可展开摘要，正式回答固定显示在其下方，产物跟随回答展示。用户正在查看过程详情时不得强制折叠或抢夺滚动位置。

产品状态：空闲、准备中、模型响应中、工具执行中、上下文整理中、正在停止、已停止、完成、失败。状态必须来自 Runtime，不能依赖前端计时猜测。

工具卡片展示工具名称、简要参数、状态、耗时、结果摘要；详情显示完整参数及可用输出。扩展工具没有专用组件时采用通用卡片。

- 网络/超时、认证失败、限流、模型不存在、协议不兼容、工具失败分别给出可理解提示。
- 恢复入口包括修改配置、重新发送、继续会话和重新启动 Runtime。
- 工具失败不一定等于整次 run 失败，由 pi 的后续执行结果决定。
- 崩溃后显示“执行已中断”，不自动重放可能已修改文件或产生副作用的工具。
- 关闭窗口时若有任务运行，提示用户留在应用或停止并退出；首版不承诺后台常驻。

### F06 厂商与模型配置（P0）

支持三条必验路径：DeepSeek、智谱 GLM 通用 API、自定义 OpenAI Chat Completions 兼容接口。

GLM 是模型家族，设置页厂商命名为“智谱 / GLM”。国际 Z.AI 和 Coding Plan 的端点、凭证不可与通用 API 混用；MVP 不单独承诺这些套餐的预设支持。

| 配置项 | 要求 |
| --- | --- |
| 厂商类型与显示名称 | 预设或自定义；允许多个独立配置 |
| Base URL | 预设可编辑；展示协议与端点示例，避免用户填写完整 chat/completions 路径 |
| API Key | 遮罩输入、替换、删除；存储后只展示已配置状态 |
| API 协议 | MVP 自定义必保 OpenAI Chat Completions；其他协议不列入验收 |
| Model ID / 显示名称 | 可手动输入；不依赖厂商必须提供模型列表接口 |
| 默认模型 | 应用默认值与当前会话选择分开保存 |
| 高级能力 | 上下文窗口、最大输出、支持的思考选项按需展开；无把握时不假装已识别 |
| 测试连接 | 主动发起最小文本请求，展示结果；明确可能产生少量模型费用 |

- 保存与测试独立，测试失败不抹掉表单。
- 模型列表拉取是后续增强，手动添加足以完成 MVP。
- “文本连接成功”不等于“工具调用兼容”；界面区分连接状态和已验证能力。
- 运行中不切换模型；用户停止后或 run 完成后可切换，历史消息保留原模型信息。
- 删除被引用的配置时提示影响；历史仍可读，再次执行要求选择可用模型。
- 缺少价格数据时不显示虚假费用；Token 使用量仅在实际获得时展示。
- Key 不进入普通配置导出、会话、诊断日志或前端持久化缓存。

DeepSeek 接口与智谱 OpenAI SDK 兼容说明分别参见 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 和 [智谱官方文档](https://docs.bigmodel.cn/cn/guide/start/introduction)。具体模型 ID 在实施时从官方目录选择并锁定测试记录，不在 PRD 中固定为“最新模型”。

### F07 Skills 与扩展兼容（P0，有限范围）

- 支持应用专属目录中的本地 SKILL.md 发现与使用，提供打开 Skills 目录和重新加载入口。
- 至少验证一个本地 Skill 能引导 Agent 完成任务。
- 不做插件市场、远程安装器、扩展管理中心或完整 pi TUI 复刻。
- 依赖终端交互/自定义 TUI 的扩展不保证兼容；基础文本工具可用通用卡片展示。
- 不默认加载用户系统另一套 pi 的配置、密钥和扩展。

### F08 设置与桌面基础（P0）

- 浅色、深色和跟随系统三种主题选择；减弱动态效果开关，默认尊重系统设置。
- 展示版本、Runtime 状态、当前 Shell 和外部工具检测结果。
- 提供打开日志目录、打开应用数据目录；日志默认脱敏。
- Windows 支持安装、启动、正常退出、覆盖升级保留数据；Ubuntu 支持开发与基础冒烟测试。
- 模型调用需要用户提供有效凭证与网络；无需用户预装 Node.js。

## 6. 视觉与动效规范

### 6.1 视觉方向

整体借鉴 Linear 的克制布局、ChatGPT Desktop 的对话可读性、Raycast 的紧凑交互。使用自己的视觉语言，不照搬品牌素材。

- 桌面工作区布局，左栏建议 240–272 px，可折叠；消息内容建议最大宽度 820–900 px。
- 最小窗口建议 960 × 640；窄窗口隐藏详情区，不把输入框挤出屏幕。
- 中性色背景、低对比边界和一个低饱和强调色；深浅主题分别调色。
- 采用 4/8 px 间距体系；圆角、阴影、图标尺寸形成少量固定 token。
- 正文字号 14–15 px，代码使用等宽字体；优先系统中文字体，不依赖远程字体加载。
- 主要层级通过排版、留白和细微背景区分，避免密集仪表盘卡片。
- 状态除颜色外必须有文字或图标；图标按钮提供 tooltip 和可访问名称。

### 6.2 动效清单

| 位置 | 动效 | 建议时长 | 限制 |
| --- | --- | --- | --- |
| 新建会话按钮 | hover 背景过渡、按压轻缩放 | 120–180 ms | 不持续发光 |
| 发送/停止按钮 | 图标与背景平滑切换 | 140–200 ms | 可点击区域不变化 |
| Agent 运行状态 | 小型呼吸点或柔和环形进度 | 1.2–1.8 s 周期 | 仅实际运行时播放 |
| 工具卡片 | 展开收起、完成状态切换 | 160–220 ms | 长输出不触发大幅布局位移 |
| 设置弹层/面板 | 轻淡入与少量位移 | 160–220 ms | 焦点与键盘行为完整 |
| 成功反馈 | 小型 check 过渡 | 120–180 ms | 不使用庆祝粒子 |

持续 token 输出不逐字做入场动画。开启 reduced motion 时关闭呼吸、缩放和位移动画，保留即时状态变化。

### 6.3 视觉验收

在 Windows WebView2 与 Ubuntu WebKitGTK 检查浅/深主题，覆盖 960×640、1440×900，以及 Windows 125%/150% 缩放。必须检查空页、长会话、长路径、代码块、运行/失败卡片、配置表单与弹层。

无横向整体溢出、文字遮挡、跳动焦点或无法到达的主按钮。Tab 可完成核心操作；焦点清晰；正文对比度以 WCAG AA 4.5:1 为设计目标。关键界面保留截图，经人工检查后才视为“好看”交付。

## 7. 非功能与质量目标

- 本地会话无网络也能浏览，发送失败可恢复。
- 在记录配置的参考机上：应用可交互冷启动目标 ≤ 5 秒；发送/停止按钮本地反馈 ≤ 100 ms；模型首 token 延迟不计入 UI 性能。
- 200 条消息、含工具卡片的参考会话切换目标 ≤ 1 秒；大输出按需加载。
- 运行日志包含时间、会话/run 标识、错误类型与耗时，默认不记录 API Key、完整提示词或文件内容。
- 应用本地执行拥有用户权限；目录信任和前端按钮不是完整隔离机制。
- API Key 使用系统凭证存储；系统凭证服务不可用时允许本次会话临时使用并说明无法持久保存，不降级为明文。
- 不设置未经测量的包体承诺；记录安装包大小、安装后大小、空闲内存和启动时间。

## 8. 明确不做

Knowledge/LLM Wiki、长期 Memory、Todo、Calendar、Project、KPI、Today 业务工作台、Weekly Summary、邮箱与网盘连接器、GitHub 同步、自动规划、定时任务、云账号同步、多人协作、多 Agent、插件市场、完整 IDE、交互式终端、自动更新服务、正式 Web/SaaS 和 macOS 发布均不属于 MVP。

详细兼容范围、测试场景和发布门槛见 [MVP 范围与验收](./mvp-scope.md)。
