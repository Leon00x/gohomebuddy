# Office Agent MVP 范围与验收

版本：v0.1 · 日期：2026-09-11 · 状态：实施基线。

## 1. 一句话边界

**MVP = 有视觉品质和少量精致动效的桌面 UI + 真实 pi Agent + 会话持久化 + DeepSeek / 智谱 GLM / 自定义兼容接口配置 + 基础文件与命令工具。**

这里的“Office”是长期产品方向。首版不承载工作管理数据，不做假工作台。

## 2. 必须交付（P0）

| 编号 | 交付项 | 最小完整形态 |
| --- | --- | --- |
| M01 | 精致桌面界面 | 左侧会话、主对话区、设置、按需工具详情；浅/深/系统主题 |
| M02 | 关键动效 | 新建会话、发送/停止、真实运行指示、工具展开、设置过渡；支持减弱动态效果 |
| M03 | 模型设置 | DeepSeek、智谱 GLM 通用 API、自定义 Chat Completions 兼容接口；增改删、测试连接、默认/会话模型 |
| M04 | 会话 | 新建、列表、标题搜索、重命名、删除、恢复；Workspace 绑定本地目录、可选的跨工作空间 Tag 分类；一个活跃 run |
| M05 | 对话 | 流式 Markdown、代码高亮/复制、文件路径引用、滚动控制、运行中编辑草稿 |
| M06 | pi 工具执行 | 文件读写编辑、搜索/枚举、Shell、工具过程和结果；停止与异常恢复 |
| M07 | 修改可见 | 文本编辑 diff 或明确的摘要降级，不提供自动回滚 |
| M08 | 基础 Skills | 本地 Skill 发现、重新加载、至少一个真实用例 |
| M09 | 数据与密钥 | pi 会话持久化、独立应用配置、系统凭证存储、脱敏日志 |
| M10 | 桌面交付 | Windows 11 x64 安装包；内置 Agent 所需 Node；Ubuntu 开发可运行 |

P0 指发布前必须完成，不等同于全部一次性并行开发。

M02、M05–M07 的具体交互及补充验收见 [Agent 执行过程交互规范](./agent-interaction.md)：执行时展开过程，结束后折叠为摘要，正式回答位于过程下方；包括逐次工具卡片、上下文整理提示和取消终态，不增加长期 Memory 功能。

## 3. 可以随后增加，但不影响 MVP 发布

- 历史正文全文搜索、置顶、归档。
- 自动生成会话标题、会话分支/树、steering 和消息队列。
- 模型列表自动拉取、更多 API 协议预设、Z.AI/Coding Plan 专用预设。
- 图片输入、拖拽文件、富附件预览、文件树、可编辑代码面板。
- GUI Skills 管理、普通扩展安装与配置。
- 任务完成系统通知、托盘和自动更新。
- 文本修改一键回滚、完整 Git diff 工作流。

上列功能如加入，应先修订范围与验收，不能因“pi 原本支持”而默认变成 UI 必做。

## 4. 本轮排除

| 模块 | MVP 不做 | 保留的未来方向 |
| --- | --- | --- |
| Knowledge | 文档导入、Wiki 生成、RAG、向量库 | 独立 Knowledge 模块和工具 |
| Memory | 自动偏好提取、跨会话召回、同步 | 独立 Memory 服务与 pi 上下文扩展 |
| Workbench | Todo、日历、目标、项目、日报周报 | UI 页面与工具共用业务服务 |
| Connector | 邮箱、GitHub、网盘、OAuth | Connector 适配器与同步任务 |
| 自动化 | 调度、后台常驻、自动规划 | 独立调度入口，复用执行服务 |
| 插件生态 | 市场、依赖管理、任意插件 UI | 延续 pi Extensions/Skills，不自造框架 |
| 平台 | Web 正式版、macOS/ARM 发布 | 前端传输层隔离、按平台构建 |
| IDE | 调试器、PTY、完整编辑器、Git 管理 | 按需求增加，非默认路线 |

## 5. 兼容承诺

### 5.1 “保留 pi 能力”

复用其 Agent Loop、Session、Context、模型调用、基础工具和 Skills 机制。MVP 不承诺完整复刻终端 UI，也不承诺任意第三方 pi package、终端交互扩展或原生依赖都能运行。

### 5.2 模型支持

必测：DeepSeek 一个有效模型、智谱 GLM 通用 API 一个有效模型、一个自定义 OpenAI Chat Completions 兼容端点。每条记录写明日期、端点、Model ID、pi 锁定版本和测试结果。

每个端点必须通过文本回复、流式输出、工具调用往返和错误提示。没有可用 Key 的测试标记“未执行”，不能用 mock 或配置页截图替代。

自定义仅承诺上述协议范围；第三方自称“OpenAI 兼容”不代表全部行为一致。支持手工 Model ID，不承诺模型自动发现、任意鉴权方式、任意网关或所有推理参数。

### 5.3 安装与编程环境

- 用户无需安装 Node.js 即可运行应用和 Agent。
- Windows 基础文件操作与命令执行不能依赖用户另装 Git Bash；先验证 pi 的 PowerShell 支持，必要时做薄工具适配。
- 应用内置的 Node 用于自身 Runtime，不等于用户项目已安装 npm、Python、Git、编译器和项目依赖。
- Python、Git、项目构建/测试在相应环境已安装时可通过 Shell 调用；设置页应检测并给出可操作信息。
- 不承诺任意项目在干净电脑上自动可构建；不自动安装系统级依赖。
- 安装包处理必要的 WebView2 前提，允许在线安装缺失运行时；“不要求预装 Node”不等于完全离线安装或内置模型。

## 6. 验收场景

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 干净 Windows 11 x64 安装与启动 | 无系统 Node 也能打开、配置模型、读写文件、执行 PowerShell 命令 |
| A02 | 配置三个必测厂商路径 | 各自完成真实流式与工具往返；错误 Key 提示明确 |
| A03 | 新建/恢复会话 | 退出重启后消息、工具记录、目录、模型引用可恢复 |
| A04 | 编程任务 | 示例目录中查找目标函数、读取、修改、验证，文件结果与界面一致 |
| A05 | 停止长命令 | 立即给出本地反馈，受控进程退出，后续工具不再启动；无虚假完成 |
| A06 | Runtime 崩溃 | 保留已保存历史，标记中断；恢复后不自动重放写操作 |
| A07 | 路径与输出 | 中文/空格路径可用；大输出折叠可读，完整输出可访问 |
| A08 | Skill | 加载一个本地 Skill 并完成其任务；重新加载有明确结果 |
| A09 | 配置变更 | 切换默认模型不改变历史；删除配置后历史可读且重新执行需选模型 |
| A10 | 视觉与键盘 | 两主题、多窗口尺寸/缩放、中文输入法、Tab、reduced motion 均检查通过 |
| A11 | 数据保护 | 日志无 Key；正常升级保留数据；凭证服务失败不写明文 |
| A12 | 单 run 限制 | 运行中浏览另一会话正常，不能意外启动第二个 run |

建议 A04 使用无需第三方包的简单示例，Windows 使用系统 PowerShell 验证文件结果；另在具备开发环境的机器验证实际项目测试命令。

## 7. 发布门槛

1. 全部 P0 与 A01–A12 有结果记录，关键真实调用不能留空。
2. 不存在阻断使用、会话丢失、密钥明文泄漏、停止失效等已知严重缺陷。
3. 完成 Windows 安装包实测；Ubuntu 成功不能替代 Windows 验收。
4. 核心页面经过人工视觉检查，动效状态与实际执行一致。
5. 保存参考机规格、包体、启动时间和长会话性能数据；未达 PRD 目标需说明原因和明确接受记录。
6. 交付源代码、锁文件、构建步骤、安装包、第三方许可说明和已知限制。

首版可以是个人测试版。若无代码签名，明确标注 Windows 可能展示未知发布者提示；正式公开分发前单独处理签名。不把缺少签名描述为安装包不存在的问题已解决。

## 8. 实施顺序

| 阶段 | 工作 | 出口条件 |
| --- | --- | --- |
| S0 技术验证 | pi SDK、三厂商、PowerShell、内置 Node、凭证存储、最小安装包 | 关键兼容可行，有版本与失败记录 |
| S1 设计与界面骨架 | 视觉 token、会话/配置布局、空/运行/错误状态、关键动效 | 可操作 UI，模拟数据仅用于开发 |
| S2 真实接入 | 会话、执行事件、工具、配置、Skills、错误恢复 | 核心工作流使用真实 pi |
| S3 发布打磨 | Windows 打包、视觉 QA、取消/崩溃验证、性能检查 | 发布门槛全部满足 |

先验证打包与 Runtime 风险，再投入完整 UI；设计探索可以在 S0 后续工作中继续。此处不虚构固定工期，S0 结束后按验证结果估算。
